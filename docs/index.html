Use Booking actions on each booking card to make the right update fast. Pick the action that matches what is happening now, add a clear reason, and confirm.

Before you confirm

  • Check booking code, customer name, and time.
  • Choose the correct action from the dropdown.
  • Enter a short, clear reason (required).

1) Reschedule

Use this when the booking needs a new time.

Use when:

  • Customer asks for a different time.
  • You are delayed and cannot start at the booked time.
  • Store operations require moving the appointment.

Result:

  • You select a new available slot.
  • Booking is moved to the new time.
  • Old slot is released.
  • Customer receives an updated booking email.

Reason examples:

  • "Customer requested later time"
  • "Consultant delayed due to prior service"

2) Cancel

Use this when the booking will not happen.

Use when:

  • Customer cancels.
  • Customer cannot be reached and confirms cancellation.
  • Service cannot be delivered.

Result:

  • Booking status changes to Cancelled.
  • Slot is released for future bookings.
  • Customer receives cancellation email.

Reason examples:

  • "Customer cancelled via phone"
  • "Service unavailable today"

3) Request reassignment

Use this when you need manager or ops help before the booking can move.

Use when:

  • No clear replacement consultant is immediately available.
  • Booking needs manager decision (priority, skill match, customer preference).
  • You want controlled escalation during busy periods.

Result:

  • A reassignment request is added to ops/manager queue.
  • Booking stays tracked until resolved.
  • Manager/store/area team can action it.

Reason examples:

  • "Need specialist skill match"
  • "No immediate replacement available"

4) Reassign now

Use this for an immediate handover to another available consultant.

Use when:

  • You are suddenly unavailable.
  • You are running late and cannot take the booking on time.
  • You need an urgent handoff to protect service flow.

Result:

  • System assigns another eligible consultant in the same store.
  • Booking remains active at the same time (unless changed later).
  • Customer receives reassignment update email.
  • Action is logged for operations visibility.

Reason examples:

  • "Urgent handover due to delay"
  • "Consultant unavailable now"

5) Mark no-show

Use this when the customer did not arrive within your store's no-show window.

Use when:

  • Customer missed appointment and did not check in.
  • Store no-show wait policy has been followed.

Result:

  • Booking status changes to No-show.
  • Record is kept for reporting and performance tracking.
  • Follow-up can be done by store team if needed.

Reason examples:

  • "No arrival after grace period"
  • "Customer unreachable at appointment time"

Important operating rules

  • The system is designed to prevent double booking.
  • Blocked consultant time is treated as unavailable.
  • Always use a clear reason so ops and managers can act fast.
  • Do not leave unresolved bookings near start time.

Quick decision guide

  • Need a new time: Reschedule
  • Booking will not happen: Cancel
  • Need manager or ops help: Request reassignment
  • Need an immediate handover: Reassign now
  • Customer did not arrive after the wait window: Mark no-show
  • If you are unsure and the booking is close to start time: Request reassignment

Store Manager

Store Manager

Common actions

Monitor queue

Track today's flow by date, status and consultant so the store queue stays balanced.

Reassign work

Move bookings when consultants are unavailable or a better operational fit is needed.

Escalate

Push cross-store pressure or unresolved bottlenecks to the area manager when local action is not enough.

  1. Log in as store manager.
  2. Open Ops/Bookings view.
  3. Filter by date, status, consultant.
  4. Monitor today's queue for your store.
  5. Reassign bookings if needed.
  6. Check no-show/cancel trends in view.
  7. Escalate cross-store issues to area manager.

Area Manager

Area Manager

Common actions

Cross-store visibility

Bottlenecks

Use status, store, consultant and date filters to spot delays or weak service flow early.

Reassignments

Move work when consultant availability changes or one store needs support from another.

  1. Log in as area manager.
  2. Open Ops filters.
  3. Select any pilot store (all 4 are in scope).
  4. Monitor Today, In Progress, Completed.
  5. Use filters for status/store/consultant/date.
  6. Reassign when consultants are unavailable.
  7. Track service flow and queue bottlenecks.

Troubleshooting (Demo)

  1. No slots: change date or service combination.
  2. Wrong login: use username + password, not display name.
  3. Missing booking: click Refresh.
  4. Cold start delay: wait, then retry once.
  5. Time checks: all booking times should display in RSA/SAST.
